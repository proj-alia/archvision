本分析记录管理界面的公开机制、采用理由与领域边界。

> 目标：回答「到底参考了 AstrBot / Koishi 的哪一部分 UI/UX」，避免空泛地写“参考插件管理”。以下为具体可复现的界面机制及 ALIA 设计决策。

## 控制台设计原则

1. 使用清晰侧栏和管理层级，避免品牌装饰遮蔽操作。
2. 不以统一统计卡片代替不同工作流。每个问题用最适合的管理控件。
3. 主视觉采用功能控制台：导航 → 列表 → 参数 → 操作 → 反馈。
4. 主流程采用工具型设计而非角色陪伴类设计。关系与身份仍在 IA 中，但不占用运维页面的中心视觉。
5. 统一操作密度：32–36px 控件、40px 表头、12–13px 管理文本、8px 圆角、1px 分割线。
6. 所有运行状态、版本、安装计数等需要区分模拟数据和真实数据。

## 不照搬的部分

AstrBot/Koishi 的平台实例、会话平台、机器人 ID、人格模型等在 ALIA 内只能是连接器、执行器、配置档案或运行服务，不能作为持续身份系统的根实体。

持续身份系统的根实体仍需有稳定 `identity_id`、人格版本、记忆来源、关系历史和自主行动授权记录。注意：UI 的连续性展示不构成对 AI 主观意识的科学证明。
