# 首版架构设计决策

本文说明当前架构选择及其理由，具体定义以领域规范、契约与专题附录为准。

| 决策 | 理由与边界 |
|---|---|
| 开放产品愿景 | 伙伴、waifu、角色、桌宠、VTuber、数字生命等表达可组合；能力由场景与验收决定，任何称呼不构成上限 |
| 持续身份采用 Identity | identity_id 独立于品牌、名字、人格、模型、账号、设备和会话；subject_id 是被描述对象，Actor/Principal 是认证行动者 |
| 模块化单体与单一状态提交 | 12 个逻辑模块保持各自状态所有权；应用用只读投影、版本引用与合法命令协调，不要求领域相互导入实现。动机是依据快照，复用机会和目标的调度/预算 |
| 模型只提供候选 | 确定性验证器、Policy、reducer 与状态存储控制事实、权限和副作用；外部内容始终保留来源与信任边界 |
| 人格可定制且受控演化 | 稳定偏好影响注意、评价与合法选择；定义发布与人格采用分开，语义变化保留必要确认。信念、范围化关系可靠性、习惯和人格分层更新；安全、隐私和权限不可作为人格偏好修改 |
| 行为由情境与经历驱动 | cognition 维护需要/评价并形成动机依据，persona 维护稳定偏好与短期情境态；有界事件/时间驱动，无校准不启用时间增长/衰减。需要缓解须有对应结果，放弃与解决分开；历史动机不自动成为承诺的持续前提，来源及自述不能循环自证 |
| 首版契约草案 1.0 | 单一结构与示例，无历史兼容入口；未来正式发布后的协议变化按实际消费者评审 |
| Rust / PostgreSQL / React | Rust Edition 2024 核心，PostgreSQL/pgvector 持久化，React/TypeScript/Vite 网页与 Tauri 2 桌面投影；精确依赖见技术清单，尚未解析构建 |
| 开放能力、受控扩展 | 业务类型由契约描述；宿主验证来源、绑定、授权、生命周期和资源，不把插件接口变成领域核心 |
| 统一管理、分工明确的业务契约 | 交互、工具、模型和媒体贡献共用宿主，但不共用平台消息协议；工具无须 ConnectorInstance，一个包可组合多类贡献 |
| 自描述交互接入 | 官方维护通用交互契约与内置 WebChat，社区提供适配实现和配置贡献；核心不列举平台；默认一包安装，声明生成表单，特殊面板受限隔离 |
| 平台交互协议插件双向桥接 | ALIA 不预知外部客户端协议；插件遵守两边协议并实现语义映射。通用接入机制不承诺不存在的外部接口或未知语义自动可执行；角色引擎不等于聊天协议 |
| 连接所有者与功能依赖分开 | 交互、渲染、工具可依赖同一逻辑连接但分别授权；connection_dependents 只保存引用，不新建状态机。配置面板走应用命令，表达片段单一执行，外部 AI 和回显不形成第二核心 |
| 定义、实例和交付分离 | 协议定义不等于实现，安装不等于连接；配置/认证/连接/业务可用性分别核验，同契约允许多个提供者；关闭管理页不停止后台连接 |
| 首版文字与完整多媒介目标 | 首版真实核心、文字 WebUI 及 fake 媒介契约先验收；真实媒体、游戏和跨设备继续有明确交付责任 |
| 功能与意识研究分开 | 数字生命可用于产品愿景；自述、记忆与自主行为不证明主观体验，研究不阻塞功能验收 |
